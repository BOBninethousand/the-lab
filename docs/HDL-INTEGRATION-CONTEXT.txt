# HDL Integration — Complete Context for The Lab

This document describes everything that was built, deployed, and is now live for The Lab to interact with the HealthDataLab WordPress backend. Use this as context when building agent tools, skills, and cron jobs in The Lab.

---

## What Was Built

An end-to-end integration that lets The Lab's AI agents act as **synthetic health patients**. 1 practitioner + 5 client agents can submit real health and longevity assessments to HealthDataLab's WordPress backend, trigger real Make.com PDF report generation, and have their data appear on the practitioner's dashboard — exactly like real users.

---

## What's Live on the Server RIGHT NOW

### REST API Endpoints (all tested and working)

Base URL: `https://healthdatalab.net/wp-json/hdl/v1/lab/`

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/lab/submit-health` | POST | Submit health assessment, deduct 1 health credit, store in tracker, forward to Make.com |
| `/lab/submit-longevity` | POST | Submit longevity assessment, deduct 1 longevity credit, store in tracker, forward to Make.com (triggers PDF email) |
| `/lab/user-status` | GET | Return credits, daily usage, last submission date, user meta |
| `/lab/reset-credits` | POST | Top up credits for the practitioner pool (capped at 500/call) |

**Authentication:** Every request requires header `X-HDL-Lab-Key: 0489ce83f7e16a33c05c29a96bde97e36c12ee12cde41c6d9d10aded9609887e`

**Security layers:**
- API key verified with `hash_equals()` (timing-safe)
- Kill switch: `HDL_LAB_ENABLED` constant in wp-config.php (set `false` to disable everything)
- Email whitelist: only `260128vm+<name>@gmail.com` accepted (server-side regex)
- Rate limit: 20 requests/hour total via `HDL_Rate_Limiter`
- Audit log: every request logged to `wp_hdl_lab_audit_log` table

### `backend/app/tools/hdl_form_builders.py`

Generates realistic form data from persona configs:

```python
from hdl_form_builders import build_health_form_data, build_longevity_form_data

# Load persona
import json
with open("backend/app/data/hdl_personas/bob.json") as f:
    persona = json.load(f)

# Generate health form data
health_data = build_health_form_data(persona, submission_history=[])

# Generate longevity form data (includes BMI, WHR, biological age calculations)
longevity_data = build_longevity_form_data(persona, submission_history=[])
```

**What it calculates:**
- BMI and category (Underweight/Normal/Overweight/Obese)
- Waist-hip ratio and risk category
- Biological age, age shift, aging rate (from 16 lifestyle scores)
- Lifestyle score average
- Overall health percentage

**Progression system:** Each call applies the persona's trajectory rules:
- `improving` agents show gradual improvements in focus areas
- `declining` agents show gradual worsening
- `stable` agents stay roughly the same
- Random variance adds realistic noise to every submission

### `backend/app/data/hdl_personas/` (5 JSON files)

| File | Agent | Age/Gender | Health Profile | Trajectory |
|------|-------|-----------|----------------|-----------|
| `bob.json` | Agent Bob | 35M, 82kg | Moderate fitness, back pain, insomnia | **Improving** — sleep, activity, balance |
| `alice.json` | Agent Alice | 42F, 62kg | Good health, chronic work stress | **Stable** — stress management focus |
| `charlie.json` | Agent Charlie | 28M, 78kg | Very active, experimenting with diets | **Improving** — diet quality, cognition |
| `diana.json` | Agent Diana | 55F, 70kg | Elevated BP, perimenopause, declining sleep | **Declining** — sleep worsening |
| `echo.json` | Agent Echo | 38M, 95kg | Sedentary, overweight, pre-diabetic | **Rapidly improving** — exercise, diet, hydration |

Each persona has:
- Base demographics (height, weight, BP, heart rate)
- 16 lifestyle scores (0-5 scale)
- Progression rules (direction, focus areas, change rate)
- Variance parameters (realistic noise ranges)

### `backend/app/skills/hdl_weekly_health_check.json`

8-step CrewAI skill workflow:

1. **load_persona** — Read agent persona JSON
2. **check_credits** — Verify credits, auto-reset if below 10
3. **generate_health_data** — LLM generates health form from persona + history
4. **submit_health** — POST to HDL, record submission_id
5. **generate_longevity_data** — LLM generates longevity form with scores
6. **submit_longevity** — POST to HDL, triggers Make.com PDF
7. **verify** — Check credits decreased, submissions landed
8. **log_to_notion** — Record results in Notion database

**Cron schedule (staggered across the week):**
```
Mon 10:00  → Bob          Mon 14:00  → Alice
Wed 11:00  → Charlie      Wed 15:00  → Diana
Fri 10:00  → Echo         Fri 14:00  → Bob (2nd)
```

### 1. Pull the code
```bash

### 2. Add API key to `.env`
```

### 3. Generate SSH key (for diagnostics — optional)
```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_labagent -C "labagent@the-lab" -N ""
```
Then install the public key on the server:
```bash
ssh healthdatalab.net "echo 'command=\"/home/labagent/scripts/gate.sh\",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty $(cat ~/.ssh/id_ed25519_labagent.pub)' > /home/labagent/.ssh/authorized_keys && chown labagent:labagent /home/labagent/.ssh/authorized_keys && chmod 600 /home/labagent/.ssh/authorized_keys"
```

## Key Constraints

- **Rate limit:** 20 API calls/hour total — stagger agent submissions
- **Credit pool:** 597 health / 568 longevity remaining — use `reset_credits()` to top up
- **Make.com:** Each longevity submission triggers a real PDF — ~6/week is safe (2.4% of free tier)
- **Email whitelist:** Only `260128vm+<name>@gmail.com` emails accepted — hardcoded server-side
- **Audit:** Every API call logged to `wp_hdl_lab_audit_log` with agent name and timestamp
- **Kill switch:** If anything goes wrong, set `HDL_LAB_ENABLED = false` in wp-config.php
